# Security Policy

## 1. Supported Versions

Security updates are applied to the active development branch of Zemo.

| Version | Supported          |
| ------- | ------------------ |
| `main`  | Yes                |
| < 1.0.0 | No                 |

---

## 2. Reporting a Vulnerability

The project maintainer takes security vulnerabilities seriously. If you discover a vulnerability or security flaw, please report it privately rather than creating a public issue or discussion.

### 2.1 Reporting Procedure

Send details regarding the vulnerability to:
* **Maintainer Email**: `mohammedsahil0003@gmail.com`
* **Subject**: `[SECURITY VULNERABILITY] Zemo - <Brief Description>`

### 2.2 Report Requirements

To help triage and resolve the issue efficiently, provide the following information:

1. **Description**: Clear description of the vulnerability and potential security impact.
2. **Component Affected**: Specific file, route, model, or service (e.g., `backend/services/`, authentication middleware, scraper endpoints).
3. **Reproduction Steps**: Step-by-step instructions or minimal proof-of-concept (PoC) payload to reproduce the vulnerability.
4. **Remediation**: Recommended patch or architectural fix, if identified.

---

## 3. Vulnerability Handling Process

1. **Acknowledgment**: The maintainer will acknowledge receipt of the report within 48 to 72 hours.
2. **Assessment**: The vulnerability report will be verified, assigned an internal severity assessment, and triaged.
3. **Patch Development**: A remediation patch will be authored in a private branch.
4. **Disclosure**: Once patched and released, coordinated disclosure will follow if applicable.
